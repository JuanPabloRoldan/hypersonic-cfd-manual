# How to use this manual

## Course vs reference

The **course** is a sequence. Lessons build on each other, tell a story, contrast choices, and end in checkpoint questions. Read them in order.

The **reference** is a lookup. Each page covers one method or model family and can be read cold. When a lesson mentions a Riemann solver, a limiter or a relaxation method, it links to the reference page, and the reference page links back to the lesson where it was taught.

The rule of thumb: the lesson is where you learn *why*; the reference is where you come back for *what exactly*.

## Depth tags

Every topic carries one of two tags.

**[deep]** means mechanical understanding: derive it where the derivation is the understanding, know the failure modes, and be able to predict how changing it changes a run.

**[feel]** means a working picture: what it is, why it exists, where it plugs into the pipeline, which codes do it, and the one or two things that matter most for results.

## The implications lens

Every method, model or setting is judged on the same six questions, and reference pages end with a table answering them:

| Lens | The question |
|---|---|
| Time step and cost | What does it do to the CFL limit, iterations to converge, cost per iteration, memory? |
| Steady vs unsteady | Is it a steady-state accelerator, time-accurate, or both? |
| Accuracy | Order, numerical dissipation, and above all wall heat flux and pressure. |
| Robustness | Positivity, shock stability, convergence stalls, sensitivity to grid quality. |
| Physics captured or lost | Which features it resolves, and which it silently smears. |
| Hardware / parallel fit | GPU vs CPU, scalability, data dependencies. |

The [implications matrix](reference/implications-matrix.md) collects these tables in one place.

## Page anatomy

Reference pages follow a fixed template, so you always know where to look:

1. **What it is**: one or two paragraphs.
2. **The problem it solves**: why the method exists.
3. **How it works**: equations, with derivations where they carry the understanding.
4. **Variants**: one section per variant, each with its own anchor so other pages can link straight to it.
5. **Implications**: the six-lens table.
6. **In a run**: the input knob that selects it, and the symptoms it produces.
7. **Which codes**: who uses it and how they differ.
8. **See also** and **References**.

## Status icons

In the sidebar, an **outline** page (hollow circle) has headings and pointers only. A **draft** page (half-filled circle) has key formulas and facts in place, but its lesson hasn't been taught yet. Pages without an icon are written.

## Hover definitions

Abbreviations such as CFL, HLLC, WENO, SWBLI or DPLR show a definition when you hover over them anywhere on the site.

## Figures

Every figure is generated by a script in the repository (`scripts/make_figures.py`), so each one can be checked and regenerated. Numbers labelled *illustrative* are order-of-magnitude teaching values, not design data.
